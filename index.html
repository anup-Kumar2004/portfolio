ChalRide is a production-grade ride-sharing Android app built entirely from scratch, featuring a complete dual-role system for riders and drivers, real-time GPS tracking, and a custom waterfall dispatch engine that sequentially targets the nearest available driver using geohash-based spatial indexing.

The matching logic, OTP verified ride starts, crash safe Firebase presence, and foreground service backed live tracking were all engineered from first principles - not tutorials, not templates. Every edge case from race conditions to driver no shows has a purpose-built solution.

🗺️
Live GPS Tracking
Real-time driver location on OSMDroid maps with smooth marker animation and bearing-aware arrow rotation
⚡
Waterfall Matching
Custom driver-assignment algorithm — targets nearest driver, falls back sequentially with a 15s per-driver timeout
🔐
OTP Verification
4-digit ride-start OTP stored in Firestore, resumable across app kills with timer-based no-show detection
📡
Foreground Services
Two foreground services — DriverLocationService + RideLiveService — keep tracking alive when app is backgrounded
🔥
Firebase Presence
RTDB onDisconnect() handles crash/kill scenarios — atomically marks driver offline and preserves active ride state
🧭
Turn-by-Turn Nav
OpenRouteService API integration for live route drawing, ETA calculation, and real-time route re-fetching every 80m

App Flows
1
GPS Pickup Detection
FusedLocationProvider + Nominatim reverse geocoding auto-detects pickup address on launch
2
Destination Search
Nominatim search with proximity bias + OpenRouteService route preview with fare estimate
3
Vehicle Selection
Real-time driver discovery via geohash grid queries — only shows available types near you
4
Live Ride Tracking
Foreground service keeps GPS tracking + OTP display alive even when app is backgrounded
5
Trip Completion
Rate driver, submit report, view trip timeline — all saved to Firestore in real-time
1
Driver Onboarding
2-step profile + vehicle setup with Cloudinary photo upload and profileStep tracking in Firestore
2
Go Online
DriverLocationService starts, RTDB presence is set, geohash updated every 5s for discovery
3
Ride Request
15-second countdown sheet with accept/reject — atomic Firestore transaction prevents race conditions
4
Navigation to Pickup
Turn-by-turn nav with heading-up map, arrival detection at 80m radius, OTP screen on arrival
5
Complete Trip
earnings += fare, totalTrips++, driver state resets to ONLINE_AVAILABLE atomically
1
Geohash Grid Query
Center hash + NxN grid (radius-dependent) fetches all online/available drivers from Firestore
2
Haversine Filter
Exact distance calculated for each candidate — only drivers within selected radius are shown
3
Proximity Sort + Target
Nearest driver gets the ride request written to Firestore with targetDriverId
4
15s Response Window
Listener watches for accepted/rejected/timeout — auto-advances to next driver on no response
5
Atomic Accept Transaction
Firestore transaction verifies ride is still pending before confirming — eliminates race conditions
1
RTDB Presence System
onDisconnect() handler auto-marks driver offline on crash — distinguishes idle crash from mid-ride crash
2
Driver Offline Watchdog
5-minute countdown on rider side — auto-cancels ride and increments driver warning count if driver disappears
3
No-Show Detection
2.5-minute OTP countdown at pickup — dialog prompts driver to cancel or wait, then auto-resolves
4
Warning/Suspension System
offlineCancelCount tracked per driver — stage 1/2 warnings shown, account suspended at 6 strikes
5
Progressive Warning System
offlineCancelCount tracked per driver in Firestore — strikes 1-3 show an informational warning, strikes 4-5 trigger a final account at risk warning, strike 6 suspends the account. Dialog shown on every app open until resolved.
6
Network Status Banner
ConnectivityManager.NetworkCallback on rider side — real-time offline/unstable/online banner in RideLiveFragment
